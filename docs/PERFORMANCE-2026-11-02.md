# TokenBar 性能优化验证

验证日期：2026-11-02。平台为 Apple M4、16 GiB 内存的 macOS；优化前安装版对应 `a202f17`，本报告对应 [v0.1.1-plus.1 性能优化预览版](releases/v0.1.1-plus.1.md)。

## 根因与改动

原版每次刷新都会启动一次 helper，重新解析日期范围内的 Codex／Claude 日志。1 秒设置与 0.1 秒文件事件合并共同触发扫描；慢扫描后的立即追扫及零等待定时刷新，使活跃会话期间的 helper 连续占用多个 CPU 核心。

本次将常规刷新接入常驻 helper，通过标准输入输出逐行交换请求和快照。文件解析结果仅驻留进程内存，按文件大小、纳秒级修改时间、ctime、设备号和 inode 判断变更；日期、价格、别名和子会话归属每轮重新处理。历史与指定日期查询沿用独立进程，便于保持常规刷新响应。

自动文件事件与定时刷新共用待处理任务，合并扫描期间的新事件，并在慢扫描后保留等待。手动刷新与真正空闲后的唤醒继续立即执行。在途额度查询由独立任务持有，调整计时器时可继续发布结果。常驻解析默认使用两个 Rayon 线程，显式开发环境覆盖值继续优先。

## 固定输入对比

基准将本机 Codex 日志通过 APFS 克隆为固定输入，共 2,537 个 JSONL、约 10.2 GiB；两版均由 helper 按原有规则选取默认 30 日范围，采用 UTC 与离线价格。原版执行三轮，修复版在同一个 worker 中执行一轮冷扫描和五轮热扫描。下表采用各组中位数，CPU 秒为进程累计 CPU 时间，区别于墙钟耗时。

| 指标 | 原版 | 修复版 |
| --- | ---: | ---: |
| 稳定刷新墙钟耗时 | 2.58 秒 | 0.278 秒 |
| 稳定刷新 CPU 时间 | 4.67 CPU 秒 | 0.29 CPU 秒 |
| 首轮墙钟耗时 | 2.78 秒 | 4.05 秒 |
| 单次／整段过程 RSS 峰值 | 544～571 MiB | 464 MiB |

首轮需要建立进程内缓存；较低的并行度增加了首轮墙钟耗时。缓存建立后，稳定刷新墙钟耗时下降约 89%，CPU 时间下降约 94%。六次修复版响应与原版逐字段一致；比较时排除生成时间，并对标题、预览及路径采用哈希。

另在固定输入中最大的 406.7 MiB 会话文件末尾，每轮追加 522 字节合成事件，连续比较三轮。修复版墙钟耗时为 0.997／0.577／0.557 秒，CPU 时间为 0.75／0.58／0.57 CPU 秒；原版分别为 4.53／3.98／3.92 秒与 5.01／4.60／4.52 CPU 秒。三轮快照均一致，修复版响应后的 RSS 约 263～271 MiB。该测试体现整文件变更失效后的开销，当前实现仍会重新解析发生变化的文件。

## 实际应用采样

两版均保留用户原有 1 秒设置，在活跃会话期间分别采样 35 秒，间隔约 0.15 秒；数据来自 `ps`，属于运行采样而非固定输入实验。100% CPU 表示一个逻辑核心。

| 指标 | 原版 | 修复版 |
| --- | ---: | ---: |
| 主程序与 helper 合计 CPU 采样均值 | 152.94% | 35.14% |
| helper CPU 采样均值／峰值 | 151.19%／369.7% | 31.09%／88.4% |
| 主程序与 helper 合计平均 RSS | 403.69 MiB | 421.78 MiB |
| 主程序与 helper 合计峰值 RSS | 632.16 MiB | 562.61 MiB |
| 观察到的 helper PID 数 | 14 | 2 |

修复版的两个 helper 分别承担常驻解析和原有记忆遥测接收。CPU 采样均值下降约 77%，峰值 RSS 下降约 11%；常驻缓存与更频繁的界面更新使平均 RSS 增加约 18 MiB。当前优化的主要收益在 CPU 和刷新延迟，活动期间仍应预留数百 MiB 运行内存。

## 正确性、隐私与进程回收

1. Swift 43 项、Rust 25 项测试通过，覆盖缓存失效、日期与价格变化、子会话归属、部分 UTF-8 末行、读取失败后重试、队列超时、取消、错误及 EOF 恢复、旧 helper 兼容和额度重排。
2. 解析缓存采用类型化对象，估算预算为 64 MiB、最多 4,096 项，30 分钟过期；近期访问条目受保护，略超预算的工作集仍保持部分稳定命中。单条派生数据超预算时继续按原文件计算。
3. 标题、预览和源路径只在进程内复用；原有快照脱敏规则保留，实机落盘快照中的这些私密字段计数为零。合成哨兵验证解析缓存实现产生的新增磁盘文件为零。
4. 主动终止解析 worker 后，应用自动创建新 PID 并恢复快照更新，主程序 PID 保持一致。应用退出后，解析与记忆接收进程在约 0.16 秒内全部退出；停止链也覆盖空闲 worker，后续可重新建立进程。
5. 设置逐项比较一致，1 秒选项保留。安装包与安装后应用的签名校验通过，应用已重新启动，快照持续更新。首次启动、worker 重建及较大的变更文件仍会产生一次较重的解析。

固定输入克隆与临时逐会话快照在比较完成后已清理；本地仅保留聚合指标、数值采样、测试日志和脱敏验证结论。本报告随本版源码保存，发行资产及安装方法见[发布说明](releases/v0.1.1-plus.1.md)。
